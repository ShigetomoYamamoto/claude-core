# ADR-026: 実行ガードの判定軸をモデルから役割へ

**ステータス**: accepted

**日付**: 2026-08-06

## コンテキスト

ADR-016 で導入し ADR-020 で思考ティア全体に拡張した `hooks/opus-execution-guard.py` は、
transcript の直近 assistant の `message.model` を読み、それが思考ティア
(`claude-opus-*` / `claude-fable-*` / `claude-mythos-*`) の場合にのみ Edit/Write/変更系 Bash を
ブロックしていた。

ADR-024 で既定のメインループが Sonnet になった結果、この判定は**通常運転では一度も発火しない**。
稀なエスカレーション時にしか効かないため、「メインは思考・計画・管理に専念し、実作業は
より安価で速い実行層が担う」という役割分担は、規範としては存在しても仕組みとしては
存在していなかった。

判定軸が目的とずれていた。止めたいのは「思考ティアが編集すること」ではなく
「メインループが実作業をすること」である。前者はモデルの属性、後者は役割の属性。

## 検討した選択肢

1. **現状維持** — エスカレーション時のみ強制。既定の Sonnet 主ループでは何も担保されない。
2. **メインのツールセットから Edit/Write を外す**(エージェント定義の `tools:`) — 実測の結果、
   `Bash` を落とすと `/autorun` の起動時チェック(test/lint/typecheck の実在検出、
   ブランチ確認)が実行できず、委譲先そのものが動かない。`Skill` も列挙しないと消えるなど
   allowlist の取りこぼしが恒常化する。ツール層では表現できない。
3. **判定軸を役割へ変える**(採用) — stdin の `agent_id` の有無だけでメインループと実行層を
   区別する。モデルは見ない。

## 決定

**選択肢3を採用する。**

- ガードは **`agent_id` の有無のみ**で判定する。モデル判定(`read_latest_model` /
  `is_thinking_model`)と transcript 読み取りを削除する。
- メインループ(= `agent_id` なし)は Edit/Write/MultiEdit/NotebookEdit と変更系 Bash を
  実行できない。**モデルは問わない**。
- **例外は固定パス2箇所のみ**: auto-memory (`~/.claude/projects/*/memory/`) と
  セッション scratchpad。「設定ファイルかプロダクトコードか」という意味による分類は
  採用しない — claude-core のような設定リポジトリでは両者が同一ファイルであり、
  パスに落とせないため。
- ブロックは `exit 2`(決定的)とする。`permissionDecision: "ask"` は
  「確認 → 承認 → メインが自分で実行」となり委譲が発生せず、目的を達しないため採らない。
- 判定不能時(パスが取得できない等)は従来どおり fail-open (ADR-006)。
- 読み取り系 Bash は引き続き許可する。メインが検証役(maker ≠ checker)であるために
  「目」が要るため。

## 結果

### Positive

- 既定構成(Sonnet 主ループ)で役割分担が初めて機械的に担保される。
- transcript 読み取りが不要になり、hook が単純化する。判定が入力1個(`agent_id`)に依存する
  だけになり、挙動が予測しやすい。
- maker ≠ checker が成立する。メインが実作業をしないため、メインが検証役になれる。

### Negative

- **専門エージェントが導入されていないプロジェクトでは委譲先が乏しい。** foundation は
  プロジェクトローカル導入方針のため、`agents/` を持たないプロジェクトが実在する。そこでの
  委譲先は組み込みの `general-purpose` のみで、これは親のモデルを継承するため、思考ティアで
  動いていると高コストかつ役割外になる(`rules/role-separation.md` が禁じている経路)。
- 些末な1行修正でも委譲の往復が発生する。委譲1回あたりの固定オーバーヘッドは実測で
  45,000〜82,000 トークン規模であり、小さい作業ほど不利になる。分岐点は未測定。
- ADR-016 / ADR-020 / ADR-024 が記述する「思考ティアを対象とする」という説明は、本 ADR 以降は
  当てはまらない。各 ADR 本文は改変せず、本 ADR が判定軸を置き換えるものとして扱う。
- Bash 経由の書き込み(ヒアドキュメント、`python3 -c` など)はコマンド文字列の検査では
  捕捉できず、この軸変更では解決しない。既知の未解決課題として残る。
