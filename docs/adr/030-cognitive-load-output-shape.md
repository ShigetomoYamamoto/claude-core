# ADR-030: 認知負荷を下げる出力形状を collaboration-style に取り込む — i-have-adhd の10ルール中8つを採用

**ステータス**: accepted

**日付**: 2026-09-15

## コンテキスト

### きっかけ

[i-have-adhd](https://github.com/ayghri/i-have-adhd)(MIT / star 45k)の評価中、本人から
「もうこの時点で内容が頭に入ってきてないです。認知の負荷を頭が処理しきれてない」という指摘を受けた。
指摘が出た時点の応答は同一セッションで 4,943字 → 約4,000字であり、当のスキルを評価しながら、
そのスキルが対象とする問題そのものを実演していた。

### 当初の判定とその誤り

最初の判定は「導入しない。既存の `rules/collaboration-style.md` と重複するため」だった。
この判定は**既存ルールが機能していることを前提にしていた**。実測はそれを否定する。

トランスクリプト実測(2026-09-01〜09-15、`~/.claude/projects/*/*.jsonl`):

- ユーザー1発話あたりに表示された文字数合計の中央値: DWAI-app 1,260字 / nakama-survey 1,583字
- 同 p90: 2,274字 / 3,805字
- 締めの定型句(「お役に立て」「他に何か」「以上です」)は 6,158turn 中 **0件**
- 前置き型は残存(「確認します」38件 /「まず」30件)

`collaboration-style.md` には既に "Conclusion first, then reasoning. Concise" があり、
memory `plain-language-explanations` には「わからない/噛み砕いて」の是正が24回以上記録されている。
**それでこの数字である。** 規範として書いてあることと、実際に守られることは別だった。
「重複しているから不要」は、重複先が効いていない場合には成立しない。

## 決定

i-have-adhd の10ルールのうち **8つを `rules/collaboration-style.md` の "Answer shape" に取り込む**。
2つは明示的に採用しない。

### 採用する8つ

4群に整理して記載する(原文のルール番号を併記)。

| 群 | ルール |
|---|---|
| 読む量を減らす | R10 前置き・まとめ直し・締めの挨拶を書かない / R4 別論点は本題の後に1件だけ |
| 先頭で答える | R1 1行目は結論か次の行動 / R2 2手以上なら番号付きリスト |
| 記憶の負担をなくす | R5 毎ターン現在位置を再掲 / R7 何ができるようになったかを具体で書く |
| 時間を具体にする | R3 未解決は2分以内にできる1件で締める / R6 見積もりは分・時間で言う |

**採用できる根拠は共通している。この8つには情報を削る指示が無い。** すべて提示の形だけを変える
ルールであり、正確さ・網羅性とのトレードオフにならない。本文にも
"presentation only; never drop information to satisfy these" と明記する。

### 採用しない2つ(棄却した代替案)

| ルール | 棄却理由 |
|---|---|
| R8「エラーは原因→修正で述べよ」 | 上流自身の評価で唯一一貫した退行。`partial-success` ケースが −0.63、採点者所見「証拠なしに原因を断定し具体的修正を処方」。作者は「形式が原因の捏造を促す機序」として追試を推奨している(n=3のため未確定)。本人の直近の主業務は原因不明の不具合切り分けであり、かつ「上流のコードは確認しましたか」「AWSの更新履歴は追えないのですか」と断定を押し返す行動が反復して観測される。最も避けるべき副作用。 |
| R9「リストは1グループ5件まで」 | 「レポートが取れない原因として考えられるものを列挙して」のような網羅列挙の依頼が実在する。表示を打ち切ると依頼そのものを損なう。上流でも 2026-09-08〜09-10 に3回書き直された未安定箇所(issue #96)。 |

### スキル自体は導入しない

`skills/` へのインストールは行わない。理由は2つ。

1. **口調のドリフト。** R1/R10 の例文はすべて英語の命令形で、日本語に写すと だ体・命令形に流れる。
   memory `polite-japanese-required`(2026-08-28「タメ口で話さないでください」)は、まさに
   「簡潔さを優先して敬体を欠いた」失敗の記録であり、同じ経路を踏む。
2. **上流の評価は現行版を測っていない。** `evals/RESULTS.md` の実行日は 2026-08-02、
   `SKILL.md` の最終変更は 2026-09-10(R9 を3回改訂)。公開されている加重 +0.427 は現行の
   成果物の証拠にならない。加えて全14ケースが英語プロンプト・試行3回・生成と採点が同一モデル・
   1ケース(`agent-owned-edit`)が構造的に通過不能。

ルールとして自前の文言で取り込めば、口調は `polite-japanese-required` の管轄下に残り、
上流の版ずれとも切り離せる。

## 既存ルールとの調停

R4(脱線抑制)は、同ファイルの "Be a critical sounding board" —「flawed assumptions・
missing risks を能動的に surface せよ」と競合しうる。

**調停: R4 はリスク指摘を先送りするが、取り消さない。** 本題を終えた後に1件として出す。
本文にも "This defers the sounding-board duty above; it never cancels it." と明記する。

## 影響

- `rules/collaboration-style.md` が 44行 → 約60行。`rules/` は毎セッション全文ロードされるため、
  恒常的なコンテキストコストが約16行増える([ADR-022](./022-autorun-flow-out-of-always-loaded-rules.md))。
  今回は本人が実害を申告している問題への対処であり、この増分は妥当と判断する。
- 遵守率には天井がある。既存の "Concise" が守られていなかった以上、同種のルールを足しても同じ
  天井にぶつかりうる。**効果は次回以降のセッションの実測(同じ集計手順)で確認する。**
  改善が見られない場合、規範ではなく機構(hook / output style)による強制を検討する。

## 検証

- 集計手順: `~/.claude/projects/*/*.jsonl` から、ユーザー発話を区切りとしてアシスタントの
  text ブロック長を合計する。思考ブロックは除外、ツール実行中の途中報告は含む。
- 再測定の目安: 中央値 1,300字 → 800字以下。
